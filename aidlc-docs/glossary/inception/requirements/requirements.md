# 용어집 퀴즈 페이지 - 요구사항 문서

## Intent Analysis

| 항목 | 내용 |
|------|------|
| **사용자 요청** | `/api/glossary` API를 활용한 용어집 퀴즈 페이지 구성 |
| **요청 유형** | New Feature (신규 페이지 추가) |
| **범위** | Single Component (프론트엔드 페이지 1개 + 라우트 추가) |
| **복잡도** | Simple (기존 API 활용, 프론트엔드 단독 구현) |

---

## Functional Requirements

### FR-1: 퀴즈 페이지 (단독 페이지)

- 용어집 퀴즈만을 위한 독립 페이지로 구성
- 라우트: `/glossary` (신규)
- 페이지 진입 시 `/api/glossary`에서 전체 용어 목록을 조회

### FR-2: 퀴즈 형식 - 설명 → 용어 맞추기

- 용어의 `description`(설명)을 문제로 제시
- 4개의 보기로 `term`(용어)을 표시 (1개 정답 + 3개 오답)
- 오답 보기는 같은 `category` 내에서 우선 선택, 부족 시 다른 카테고리에서 보충
- 보기 순서는 랜덤 셔플

### FR-3: 랜덤 2문제 출제

- 전체 용어 목록에서 랜덤으로 2개를 선택하여 퀴즈 생성
- 2문제는 서로 중복되지 않아야 함

### FR-4: 즉시 정답/오답 피드백

- 사용자가 보기를 선택하면 즉시 정답/오답 표시
- 정답 시: 정답 보기 강조 (초록색 등)
- 오답 시: 선택한 보기 오답 표시 (빨간색) + 정답 보기 강조
- 피드백 후 해당 문제의 보기는 비활성화 (재선택 불가)

### FR-5: 새 퀴즈 재생성

- "다른 퀴즈" 버튼 제공
- 클릭 시 새로운 랜덤 2문제를 즉시 생성
- 이전 퀴즈 결과는 초기화

## Non-Functional Requirements

### NFR-1: 기존 기술 스택 준수

- React 18 + TypeScript + Tailwind CSS (기존 프론트엔드 패턴 유지)
- `react-router-dom` 라우트 추가
- API 호출: `fetch` 사용 (기존 패턴과 동일)
- 환경변수: `VITE_API_BASE_URL` 사용 (프로덕션: `https://www.homefit1403.site/api`)

### NFR-2: UX

- 로딩 상태 표시 (API 호출 중)
- API 에러 시 사용자 친화적 에러 메시지
- 모바일 반응형 레이아웃

## Technical Notes

- **API 스펙**: `GET /api/glossary` → `GlossaryEntry[]`
  - `term`: string (용어명)
  - `category`: '소득기준' | '주택정보' | '자격요건' | '공급유형'
  - `description`: string (설명)
  - `related`: string[] (관련 용어)
- **퀴즈 로직**: 프론트엔드에서 처리 (서버 변경 불필요)
  - API에서 전체 목록 조회 → 클라이언트에서 랜덤 선택 및 보기 생성
- **최소 용어 수 요건**: 퀴즈 생성을 위해 최소 4개 이상의 용어가 DB에 존재해야 함
  - 4개 미만 시 퀴즈 대신 안내 메시지 표시
