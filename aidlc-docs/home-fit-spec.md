# home-fit 서비스 요구사항 명세서

> 팀 #1403 | 프로젝트명: home-fit

---

## 1. 서비스 개요

SH 서울주택도시공사의 임대/분양 공고문(PDF)을 AI가 자동 분석하여, 사용자가 간단한 Q&A만으로 자신의 공공주택 신청 자격과 필요 금액을 확인할 수 있는 웹 서비스.

### 핵심 가치

- 수십 페이지 PDF 공고문을 사용자가 직접 읽을 필요 없음
- 소득 기준표, 자격 조건 등 복잡한 교차 확인을 AI가 대신 처리
- 비전문가도 이해할 수 있는 쉬운 용어 해설 제공

---

## 2. 사용자 시나리오

### 2.1 최초 방문 (온보딩 포함)

```
첫 방문
  └─ 온보딩 (기본정보 입력)
       └─ 프로필 저장 (로컬 스토리지)
            └─ 공고 목록 조회 → 공고 선택 → Q&A (추가 질문만, 1~3개) → 결과 확인
                                                                        ├─ 적합    → 신청 가능 단지/평형 + 비용 안내
                                                                        ├─ 부적합  → 탈락 사유 안내
                                                                        └─ 조건부  → 원본 공고 확인 권장
```

### 2.2 재방문 (프로필 보유)

```
재방문
  └─ 프로필 로드 (자동)
       └─ 공고 목록 조회 (프로필 기반 사전 필터링 적용)
            └─ 공고 선택 → Q&A (공고별 추가 질문만) → 결과 확인
```

### 공통 사항

- 로그인 없이 모든 기능 이용 가능 (인증 없음)
- 온보딩에서 수집한 기본정보는 이후 Q&A에서 재사용되어 중복 질문 제거
- 사용자는 언제든 프로필을 수정할 수 있으며, 수정 즉시 이후 Q&A에 반영됨

## 3. 기능 요구사항

### 3.1 공고 자동 수집

- SH 임대/분양 게시판을 n시간 주기로 크롤링
- 새로운 공고 감지 시 PDF 분석 파이프라인 자동 트리거
- 수집 대상: 임대(장기전세, 국민임대, 행복주택 등) + 분양

### 3.2 AI 공고 분석

- PDF 공고문에서 다음 정보를 구조화하여 추출:
  - 주택 유형 (장기전세, 국민임대, 행복주택, 공공분양 등)
  - 접수 기간 (시작일, 마감일)
  - 단지별 자격 조건 (소득 기준, 자산 한도, 거주 요건 등)
  - 단지별 비용 정보 (보증금, 월세, 분양가 등)
  - 공급 유형 (일반공급, 특별공급 - 신혼부부/청년/장애인 등)
- 분석 결과로 Q&A 상태 머신을 자동 생성

### 3.3 사용자 프로필 (온보딩)

#### 온보딩 진입 조건

- 최초 방문 시 자동으로 온보딩 화면 표시
- 프로필이 이미 존재하면 온보딩 스킵, 공고 목록으로 바로 이동
- 공고 목록 또는 마이페이지에서 언제든 프로필 수정 가능

#### 수집 항목 (공통 기본정보, 3~5개)

| 항목 | 입력 유형 | 설명 |
|------|-----------|------|
| 거주지 (시/구) | 선택지 | 서울시 자치구 선택 |
| 가구원 수 | 숫자 입력 | 본인 포함 세대원 수 (명) |
| 무주택 여부 | 예/아니오 | 세대원 전원 무주택 여부 |
| 월 평균 소득 | 숫자 입력 | 세대 전체 월 평균 소득 (만원) |
| 자산 보유 현황 | 선택지 | 부동산/금융자산 보유 여부 (대략적 범위) |

> 항목은 공고 분석 결과에서 가장 빈번하게 등장하는 자격 조건 기준으로 선정하며, 추후 조정 가능

#### 저장 방식

- 기본: 브라우저 로컬 스토리지에 저장 (서버 전송 없음, 개인정보 최소화)
- 저장 형식: `UserProfile` 객체 (4.4 참조)
- 만료: 별도 만료 없음 (사용자가 직접 삭제하거나 수정)

#### Q&A에서의 프로필 활용

- 각 공고 Q&A 시작 전, 서버의 상태 머신 질문 목록과 프로필 항목을 매핑
- 프로필에 이미 답변된 항목에 해당하는 질문은 자동 스킵 (사용자에게 "프로필 정보 사용됨" 표시)
- 스킵된 항목은 결과 화면에서 "프로필에서 가져온 정보"로 요약 표시
- 사용자가 특정 질문에서 프로필 값을 재입력하고 싶을 경우 "직접 입력" 옵션 제공

#### 공고 목록 사전 필터링

- 프로필의 무주택 여부, 소득, 거주지 등을 기준으로 자격 가능성이 낮은 공고에 시각적 표시 (예: 흐리게 처리 또는 "조건 불일치" 배지)
- 필터링은 참고용이며, 사용자가 원하면 해당 공고의 Q&A도 진행 가능

### 3.4 Q&A 자격 확인

- 서버가 생성한 상태 머신 기반으로 동작
- 질문 유형: 예/아니오, 숫자 입력, 선택지
- 일반공급 + 특별공급(신혼부부, 청년, 장애인 등) 자격 판단
- 이전 답변에 따라 다음 질문과 기준값이 동적으로 결정됨 (예: 가구원 수에 따라 소득 기준이 달라짐)
- 진행률 표시 (progress bar)

#### 프로필 기반 질문 최소화

- Q&A 시작 시 상태 머신의 전체 질문 목록을 프로필과 대조
- **자동 스킵 조건**: 질문의 `profile_key`가 프로필에 존재하고, 해당 값이 유효한 경우
- **추가 질문만 표시**: 프로필에 없는 항목 또는 공고별 특수 조건에 해당하는 질문만 사용자에게 노출 (목표: 1~3개)
- **스킵 항목 표시**: Q&A 화면 상단에 "프로필에서 자동 적용된 정보" 섹션으로 요약 표시, 수정 링크 제공
- **수동 재입력**: 사용자가 스킵된 질문의 값을 변경하고 싶을 경우 "수정" 버튼으로 해당 질문 재활성화 가능
- 재입력한 값은 해당 Q&A 세션에만 적용되며, 프로필 영구 수정은 별도 확인 후 반영

### 3.5 결과 안내

#### 적합

- 신청 가능한 단지/평형 목록 표시
- 각 단지별 비용 구조 안내:
  - 장기전세: 전세보증금
  - 국민임대: 보증금 + 월 임대료
  - 공공분양: 분양가 + 계약금 + 중도금 + 잔금
- 원본 공고 링크 제공

#### 부적합

- 구체적인 탈락 사유 안내
- 원본 공고 링크 제공

#### 조건부

- 추가 확인이 필요한 항목 안내 (warnings)
- 원본 공고 확인 권장
- 해당되는 단지 정보도 함께 표시

### 3.6 용어 사전

- AI가 생성한 공공주택 용어 해설
- 별도 용어 사전 페이지 제공
- Q&A 진행 중 관련 용어에 대한 contextual 툴팁 표시
- 카테고리: 소득기준, 주택정보, 자격요건, 공급유형

## 4. 데이터 모델 (예시 — 구현 시 변경될 수 있음)

### 4.1 공고 목록 (AnnouncementSummary)

| 필드 | 타입 | 설명 |
|------|------|------|
| seq | string | 공고 고유 번호 |
| title | string | 공고 제목 |
| housing_type | string | 장기전세, 국민임대, 행복주택 등 |
| supply_category | "임대" \| "분양" | 공급 유형 |
| status | "진행중" \| "예정" | 공고 상태 |
| application_start | string \| null | 접수 시작일 (YYYY-MM-DD) |
| application_end | string \| null | 접수 마감일 |
| unit_count | number | 공급 세대 수 |

### 4.2 Q&A 상태 머신 (QAStateMachine)

| 구성요소 | 설명 |
|----------|------|
| initial | 시작 질문 state ID |
| states | 질문(QuestionState) 또는 결과(ResultState) 노드의 맵 |
| meta.total_questions | 전체 질문 수 (진행률 계산용) |

#### QuestionState

- text: 질문 내용
- input: boolean \| number \| choice
- unit: 숫자 입력 시 단위 ("만원", "명")
- options: choice 입력 시 선택지 배열
- profile_key: 프로필 항목 키 (있으면 프로필 값으로 자동 스킵 가능, 예: `"household_size"`, `"monthly_income"`)
- help.ref: 용어 사전 참조 키
- transitions: 조건부 전이 배열 (순서대로 평가, 첫 매칭 적용)

#### ResultState

- result: "적합" \| "부적합" \| "조건부"
- reason: 탈락 사유 (부적합 시)
- warnings: 확인 필요 항목 (조건부 시)
- units: 신청 가능 단지 목록 (적합/조건부 시)
- source_url: 원본 공고 링크

#### ResultUnit (단지 정보)

| 필드 | 설명 |
|------|------|
| complex_name | 단지명 |
| location | 소재지 |
| unit_type | 평형 타입 (예: "59B") |
| area_sqm | 전용면적 (m2) |
| supply_count | 공급 세대 수 |
| track | 공급 트랙 ("일반공급", "특별공급(신혼부부)" 등) |
| cost | 비용 항목 배열 (label, amount, period) |

### 4.4 사용자 프로필 (UserProfile)

| 필드 | 타입 | 설명 |
|------|------|------|
| district | string | 거주지 자치구 (예: "강남구") |
| household_size | number | 가구원 수 (명) |
| no_house | boolean | 세대원 전원 무주택 여부 |
| monthly_income | number | 월 평균 소득 (만원) |
| asset_range | string | 자산 보유 범위 (예: "1억 미만", "1억~3억", "3억 초과") |
| updated_at | string | 마지막 수정 일시 (ISO 8601) |

> `profile_key`는 `QuestionState`에서 이 필드명을 참조하여 자동 스킵 여부를 판단함

---

| 필드 | 설명 |
|------|------|
| term | 용어명 (Q&A help.ref와 매칭) |
| category | 분류 (소득기준, 주택정보, 자격요건, 공급유형) |
| description | 쉬운 말 설명 |
| related | 관련 용어 목록 |

## 5. API 엔드포인트 (예시 — 구현 시 변경될 수 있음)

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | /announcements | 활성 공고 목록 조회 (필터: board, housing_type, status) |
| GET | /announcements/{seq} | 공고 상세 + Q&A 상태 머신 조회 (200: 분석 완료, 202: 분석 중, 404: 없음) |
| GET | /glossary | 용어 사전 전체 조회 |

## 6. 비즈니스 규칙

- 공고 목록에서 status가 "마감" 또는 "공지"인 항목은 제외
- Q&A 상태 머신의 전이 조건은 순서대로 평가하며, 첫 번째로 매칭되는 조건을 적용
- 비용(amount)은 원(KRW) 단위로 저장

---

## 7. 향후 확장 (MVP 범위 밖)

- 공고 자동 추천: 사용자 프로필 기반으로 자격이 되는 공고를 자동으로 찾아 추천 (채팅 인터페이스 또는 목록 필터)
- 새 공고 알림: 프로필 조건 기반 푸시/이메일 알림

## 8. 프로덕트 전체 컬러톤

- orange 를 기본 색상으로 하며 전체 페이지를 어울리는 색상으로 UI를 구성한다.
